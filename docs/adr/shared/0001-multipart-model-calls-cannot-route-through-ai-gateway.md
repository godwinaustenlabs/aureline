# Multipart model calls cannot route through AI Gateway, and the helper refuses one rather than degrading

ADR-0006 says every Workers AI call made through `packages/shared-utils` passes a gateway configuration as `ai.run`'s third argument. That decision was taken when every call carried a JSON body. `getImageToImageOutput` does not: the flux-2-klein family rejects a JSON body with `5006: required properties at '/' are 'multipart'`, so the call carries binary. Iris has never once succeeded in routing it through the `iris` gateway, and `docs/ai-gateway-multipart-findings.md` records a sprint's worth of things ruled out — three models, three body encodings, two image sources, the field name, the input size. None of them moved the error.

The cause is now established, and it is not what the findings doc suspected. A probe on 2026-08-31 sent three body shapes to `@cf/black-forest-labs/flux-2-klein-9b`, each one twice, with a gateway and without:

| `multipart.body` | direct | through the gateway |
|---|---|---|
| string | `8001: Invalid input` | `8001: Invalid input` |
| `Blob` | `8001: Invalid input` | `8001: Invalid input` |
| `ReadableStream` | **succeeds** — a real 730 KB image | `AI Gateway does not support ReadableStreams yet.` |

**The `8001` was never the gateway's doing.** A `Blob` fails with it when no gateway is involved at all. It is what the model returns for a body that is not a stream. So the model requires a `ReadableStream`, and AI Gateway refuses one — the only body type the model accepts is the only body type the gateway refuses, and buffering around the second error produces the first. That is the whole of it.

Two earlier readings of the evidence are retired by this, and both are worth naming because both were reasonable. The gateway log showing `"body": {}` was not evidence of a lost body: a direct `Blob` call serializes to `{}` in exactly the same way and still reaches the model's validator, so `{}` in a log tells you nothing about what was forwarded. And "stream, `Blob` and `ArrayBuffer` all failed identically" was a conflation of two different failures — the stream failed with the gateway's own message, the other two failed with `8001` for being the wrong type. Read separately they point straight at the answer; read as one they look like a serialization boundary.

Decision: **ADR-0006's rule does not hold for a call carrying a multipart body, and this ADR amends it to say so.** The limit is not specific to Iris or to this model. It applies to any call whose body must be a stream, which is every image-to-image call this repo will make, `agent-atlas` included.

Decision: **`getImageToImageOutput` throws when a gateway id is passed**, before the form is built and before anything bills, unless the caller sets `allowGatewayMultipart`. The reason travels with the refusal as `MULTIPART_GATEWAY_REASON`, so the next person to try it reads a sentence instead of burning a call on an `8001` that explains nothing. The escape hatch exists so that whoever confirms Cloudflare has fixed this flips one flag, rather than finding the guard, assuming it is stale, and deleting it.

That throw is a deliberate departure from ADR-0006, which says an absent gateway id *"degrades to a direct Workers AI call rather than throwing"* because *"a missing observability layer is not a reason to fail a request."* The two cases are different in kind: an absent id is a configuration choice, while an id on a multipart call is a wiring mistake whose only other outcome is an opaque failure at the far end of a pipeline. The price of choosing the throw should be stated where someone will meet it — **in Iris the planner bills before the colorizer runs**, so a wrongly-set `AI_GATEWAY_ID` costs a planner call on every request and then fails the image stage. Degrading would have cost nothing and warned instead. We took the loud option on the grounds that a silently-ignored gateway id is how this became a sprint-long investigation in the first place.

Rejected alternative: the REST endpoints. The unified `POST /accounts/{id}/ai/run` API and the `gateway.ai.cloudflare.com` passthrough both show JSON bodies in their documentation and mention multipart nowhere. That is *undocumented*, not documented as unsupported — a weaker statement than it first appears, and not a foundation to build on. It also needs an API token the binding does not, which contradicts the standing conclusion in `.dev.vars.example` that no secret is required here. Anyone who wants that route probes it with one cheap call first.

Consequence: **`cost_usd` on Iris's image row is `null` by decision, not by accident.** No gateway means no log row means no cost, and `readGatewayCost` already tolerates that by design — *"a missing, failed or unlogged cost is always tolerated as `null`. Cost is an audit concern and must never fail a run that otherwise worked."* The findings doc listed this as the third of three options and asked for someone to decide it out loud rather than arrive at it. This is out loud. Iris's text row still carries a real planner cost, so cost reporting degrades on one modality rather than disappearing.

Consequence: `atlas-07` meets this identically — it sends two input images through the same helper — and now gets a sentence rather than an opaque failure.

One further fact fell out of the probe and belongs with this decision, because it constrains how the call may be written. **The `Response` that serializes the form must stay in scope until `ai.run` resolves.** The stream is not independent of the object it came from: extracting those lines into a function that returns only `body` — an ordinary-looking refactor — makes every call fail with `3043: Internal server error`, which names nothing and looks like a platform fault. This was proved by running both arrangements against the same bytes, in-scope producing an image and out-of-scope producing `3043` with no other difference. There is a comment on it at the construction site; a caller that never touches that code cannot hit it.

Also established, and the reason the cheapest option is not available: **flux-2-klein's response carries `image` and nothing else.** No `usage`, no `neurons`. ADR-0006 derived the planner's cost from `usage.neurons` in the response body, and the same trick was worth trying here precisely because it needs no gateway. It does not work — the block is not there, so the gateway really is the only source of dollars for this call, and its refusal really does mean a null cost.

What would reverse this: AI Gateway supporting `ReadableStream`. That is a narrower and more checkable thing to watch for than "Cloudflare fixed multipart", and it is the single condition under which `allowGatewayMultipart` should be set. Do not set it on a changelog entry alone; set it on a real call that succeeded.
