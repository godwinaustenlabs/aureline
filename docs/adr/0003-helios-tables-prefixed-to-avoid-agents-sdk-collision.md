# Application tables are prefixed `helios_` to avoid colliding with the Agents SDK's internal SQLite tables

The Cloudflare Agents SDK manages its own internal tables in the same Durable Object SQLite database that Drizzle-managed application tables live in: `cf_agents_state`, `cf_agents_schedules`, `cf_agents_queues`, plus a hidden `__cf_kv` for the KV API. This was an open item in the original architecture doc ("confirm no collision between Agents SDK's own internal SQLite tables and the Drizzle-managed application schema") — confirmed via the Agents SDK docs (developers.cloudflare.com/agents/concepts/agent-class) that all SDK-owned tables live under the `cf_agents_`/`__cf_` namespace.

Decision: every Drizzle-managed table in this repo is prefixed `helios_` (e.g. `helios_runs`), and every future engine built from this template prefixes its own tables the same way with its engine name (e.g. `iris_*`, `atlas_*`). This guarantees no collision with the SDK's namespace without needing any runtime detection or migration-time check — it was never actually at risk once the SDK's naming convention was confirmed, but the prefix convention is recorded here so no future engine skips it and accidentally lands in `cf_agents_` territory by using an unprefixed or differently-prefixed name.
