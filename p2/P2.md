> **Four things §8.3 of the plan got wrong or left out, all found against the generated Workers AI types:**
>
> 1. **`tool_calls` is not under `choices[0].message` on the default research model.** `Ai_Cf_Meta_Llama_4_Scout_17B_16E_Instruct_Output` (`worker-configuration.d.ts:8187-8235`) puts it at the **top level**, types `arguments` as an **object** rather than a JSON string, and makes `id` **optional**. A Chat-Completions-only reader finds nothing there and silently reports that the model chose not to search. The loop reads all three live envelopes and a test covers each; deleting the top-level branch fails 22 of the 31 tests.
> 2. **`AI_SEARCH.search` takes `{ query }` directly.** `AiSearchSearchRequest` is a union of `{query}` XOR `{messages}` — the model already wrote the query, so wrapping it in a message array buys nothing.
> 3. **`<source>` rendering cannot live in `research.ts`.** `ToolLoopResult.chunks` carries no `text` (by design — provenance, not payload), so the loop is the only thing holding it. Rendering is here and `ToolLoopResult.context` carries the finished string; T3's Iris/Helios tests can still assert the exact rendering end to end.
> 4. **A second ceiling was needed.** `maxToolIterations` bounds billed *model* calls; `MAX_TOOL_CALLS_PER_TURN` (4) bounds *searches* honoured from one reply. Without it a reply carrying twenty tool calls fans out to twenty AI Search calls inside one "bounded" iteration — AGENTS.md §7 is about unbounded work, not only unbounded spend. Calls past the cap are still **answered** with a message saying they were not run, because an unanswered `tool_call` is a malformed transcript some providers reject.

## T2 — Classifier Stage

**What to build:** A new service in Helios that classifies a textile concept as either a tile or a motif. A small model call that reuses `getTextualModelOutput` unchanged.

**Blocked by:** T1 (needs `Classification` type, `TextModelConfig` type)

**Status:** ready-for-agent

### What to research first

Before writing code, research the classifier prompt. You need to understand:

1. **What signals distinguish tile from motif in textile design.** A tile is a seamless repeating unit (e.g., "art deco paisley", "geometric lattice"). A motif is a single design element for a garment part (e.g., "embroidered neckline", "screen-printed back panel").

2. **How to extract garment part from concept text.** "a paisley neckline" → `neckline`. "embroidered cuff" → `cuff`. No garment part mentioned + repeating pattern = tile, no garment_part.

3. **What reference images tell the classifier.** Photo of repeating scarf print = tile. Photo of embroidered neckline = motif.

4. **Edge cases:**
   - Ambiguous ("a floral design") → default to `tile`
   - Mentions garment part but describes repeat ("seamless sleeve pattern") → `tile`, no garment_part
   - Motif but no garment part ("a single peacock motif") → `motif`, no garment_part

Write the classifier prompt based on this research. Short and direct — classification, not creative. ~200–400 tokens.

## T6 — ADR for Ungated Research Call

**What to build:** Document why the research call bypasses AI Gateway, why the tool loop is a sibling helper, and why `research_cost_usd` is `null`.

**Blocked by:** None — can do anytime.

**Status:** ready-for-agent

### Acceptance criteria

- [x] New file: `docs/adr/shared/0005-the-research-call-is-ungated-and-bounded.md`
- [x] Explains:
  1. **Why ungated:** Gateway is per-binding. Research call would overwrite `aiGatewayLogId` before planner's cost can be read.
  2. **Why ordering makes this safe:** classify (gated) → research (ungated) → planner (gated). Ungated call between two gated calls, never sets `aiGatewayLogId`.
  3. **Why `research_cost_usd` is `null` not `0`:** Zero means provider didn't report, not that call was free. ADR-0007's rule.
  4. **Why sibling helper:** `getTextualModelOutput` pinned to `response_format: json_schema`. Adding tools conflicts. Retry loop mutates messages — one counter can't serve two budgets.
  5. **Why bounded:** AGENTS.md §7 requires bounded attempt count. `maxToolIterations` (default 3).
- [x] Pointer added at top of `docs/adr/shared/0006-all-model-calls-route-through-ai-gateway.md`

> **Two corrections made while writing it**, both recorded in the ADR itself rather than silently absorbed:
>
> - **Reason 1 above does not hold as stated.** `readGatewayCost` is called immediately after the call it belongs to, and the planner runs *after* research, so a gated research call would set `aiGatewayLogId` before the planner overwrote it and the planner's cost would still read correctly. Gating research would not corrupt the planner. The two reasons that do hold are: a gated research stage would report the cost of its *last* loop turn under a column named for the whole stage (`gatewayCost.ts:42-47`), which is the shape of wrong number ADR-0007's closing rule forbids; and an ungated call does *not* clear `aiGatewayLogId` (`gatewayCost.ts:35-40`), so calling `readGatewayCost` on this path would return the **classifier's** cost misattributed to research. The discipline is that nothing calls it here, which `readGatewayCost`'s `stage: "planner" | "image"` parameter already makes a compile error.
> - **The pointer path in this ticket is wrong.** ADR-0006 lives at `docs/adr/0006-…`, not `docs/adr/shared/0006-…` — the flat `0001`–`0010` are the foundational set and stay where they are (`docs/adr/README.md:3`). The pointer went in the real file.
